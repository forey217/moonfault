# MoonFault 完整 MEF 实现与验收计划

修订日期：2026-11-14。本文是项目最终交付承诺和开发计划，不是已实现功能清单。当前可安装软件仍为 0.2.0。

## 1. 最终项目终点

完整实现 Open-PSA MEF 2.0 明确定义的模型结构、语义处理与结果交换，使合法模型能够完成读入、解析、校验、计算、导出、再次读入的闭环。故障树静态子集是第一阶段成果；随机层、元逻辑层、事件树及多文件组织均属于最终交付，不能永久以“不支持”替代实现。

标准基线为 [Open-PSA MEF 2.0](https://open-psa.github.io/mef/) 页面标识的 `2.0.d-120-g703be91`，含公开正文和配套 RNC。实现时记录所用源文件版本与校验值。章节 3—9 是覆盖检查入口；每个语法产生式、约束及语义规则进一步关联具体用例，不能仅按章节数量声称覆盖率。

“完整”不等于实现所有厂商自定义扩展，也不等于无限模型规模。标准内功能不能因现有 64 事件、固定概率等实现限制而被改写为范围外；规模预算、数值精度和宿主依赖必须明确报告。最终发布前仍有必需项缺失，则继续标记阶段版本。

## 3. 实施顺序与阶段出口

1. 基线审计与通用模型：逐项登记正文/RNC 规则；建立完整类型化模型、表达式结构、源位置和引用解析器。修正 0.2.0 对隐式事件及重复定义等采取的保守限制。出口是模型结构和合法语义往返，不把“能保留未知 XML”算作语义支持。
2. 随机层与任务上下文：实现运算、时间函数、分布、单位、采样和外部接口。出口是可复算的时间点概率、分布统计及错误诊断；定义二进制浮点与统计误差标准。
3. 元逻辑与事件树：实现四类 CCF、替换语义、分支上下文、指令解释及序列/后果聚合。出口是完整输入模型到可独立核对结果的案例，不只导入或显示模型。
4. 模型组织与报告：完成多文件、阶段/任务、后果组、标准报告和宿主适配器；导出再导入保留语义与结果。
5. 一致性发布：关闭全部必需规则的缺口，发布逐项覆盖表、固定样例和独立对照报告；完成干净环境安装、四后端验证和完整实例后再发布完整实现版本。

阶段按依赖推进；当前没有将后三阶段写成已完成，也不把报名材料截止日等同于未经确认的开发完成日。最终验收以功能和证据完成为准。

## 4. 一致性验收门槛

- 每条标准规则登记来源、实现位置、状态、正例、反例、期望语义与执行结果。语法校验、读写保留和数值计算分别计项；失败或尚无证据的项不能记为通过。
- XML 采用标准 schema 校验加语义校验；覆盖合法复杂组合，以及引用、类型、基数、数值域、执行顺序、跨文件/跨记录错误。标准正文与 schema 不一致时单独登记并说明采用的解释，不静默修改标准。
- 往返必须比较引用身份、作用域、表达式、指令顺序、参数/单位和数值结果；不要求注释及缩进逐字节一致。由加载器显式提供文件内容，核心库不隐式访问文件或网络。
- 外部函数作为宿主注册回调，约定名称、参数和返回值。没有依赖或文件时明确报错；提供标准化测试桩及宿主案例后才能记为接口已实现，不能用永远拒绝调用冒充支持。
- 小型故障树由独立真值表检查概率及素蕴含项；时间函数与 CCF 使用独立公式/展开；事件树使用独立逐路径解释器检查状态和结果。SCRAM 支持的交集继续交叉验证，不能用 SCRAM 的实现范围缩小 MEF 范围。
- 四后端验证核心语义一致；Node 宿主另验文件解析和回调。公开包在没有本地工作区覆盖的工程中安装运行；报告明确代码提交、标准版本、工具版本、输入、容差和复现命令。

第 9 章明确报告外层没有统一的完整格式，因此实现其已给定的数据结构和信息要求，并公开外层包装约定；不把自定义包装称为官方 schema。标准中的建议、未定问题及工具扩展分别登记，不能据此豁免明确规定的功能。
